# 期限感知批作业编排庭

供离线云平台的批作业运营员判断期限承诺、执行槽租约和产物交付。SQLite 保存作业与依赖、槽与租约、尝试与产物、撤销及保留证据。三个子系统分别由 `job`、`slot`、`run` 命令调用；故障回执会改变后续承诺或交付结论。

## 数据处理许可（residency）

`cloudctl/residency.py` 把数据处理许可变成真实的执行约束，而不是提交时的地域字符串比较：

- 每份输入数据集独立登记来源地、数据类别、字段与摘要；许可按**版本**签发，必须集齐全部必需签名才生效，迟到的签名只对之后生效，不能回溯洗白先前的处理。
- 作业绑定一份**获准输入清单（manifest）**，对所有输入的处理法域、节点类别与出境规则求**交集**——任一父产物的窄许可不会被另一父作业的宽许可覆盖；交集为空时任何机房都拒绝放置。
- 物理执行节点、远端暂存（staging）和恢复点（recovery）都按处理地点校验。租约、重租（repay）、每次启动和交付都重新引用同一份清单与许可版本；控制面重启、租约抢占、清单换版都不能让旧代次回执冒充合法结果。
- 去标识化必须产生**实际的新字节**并通过可验证转换证明（输入摘要、实际丢弃字段、方法与证明摘要一致）；把原始摘要改名直接拒绝，原始字节永远不能直接出境。
- 未经许可的临时副本在写入时即生成不可抹掉的 `rviolations` 证据；事后删除字节或拿到更宽许可都不能清除该证据，且永久阻断该作业交付。
- 许可撤销只释放活动租约、阻止之后的处理与再分发；已合法交付的制品保留当时的清单/许可回执（`regress`），同时生成后续删除义务（`rdeletion_duties`）。

未登记清单的作业保持原有期限/容量行为，不受驻留层影响。`residency` CLI 命令可跨 `slot`/`run` 子系统编排，见 `fixtures/数据驻留.json`，完整语义见 `tests/test_residency.py`。

## 运行

无需第三方依赖。安装检查：`python -c "import cloudctl; print(cloudctl.__file__)"`。

```sh
python -m cloudctl init --db state.sqlite
python -m cloudctl demo --db state.sqlite --fixture fixtures/demo.json
python -m unittest discover -s tests -v
```

重新演示时删除演示数据库，测试使用独立临时数据库。`fixtures` 包含三个子系统的正常和失败输入。CLI 每行输出决定、事件及证据。状态变更在 SQLite `BEGIN IMMEDIATE` 事务中提交；失败与旧代次不会伪装成交付。
